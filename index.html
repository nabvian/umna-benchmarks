Unified Modular Neural Architecture · v0.1.0 · preliminary

Adding capabilities without silent regression

UMNA is a hypothesis about building AI systems that keep learning new things without quietly breaking what they already do: a frozen shared Core, small capability modules called Wings, a planner that picks Wings by value against cost, a calibrated gate on every answer, and a statistical gate on every update.

Read the preprint Verify the results yourself GitHub

Every test was preregistered and SHA-256 hashed before it ran. Nothing is dropped: invalid and superseded runs stay in the record. The source code is private for now; every result file is tied to a GPG-signed commit of it.

The problem

Every update touches everything

Most systems gain new abilities by fine-tuning one shared set of weights. A change that improves one task can make another worse, and often nobody notices until it matters. Mixture-of-experts routers are learned too, with no notion of what each expert is for. And it is usually hard to say which parts produced an answer, or whether last week's update was allowed to change it.

The hypothesis

Five properties that can fail

  1. Add new capabilities without changing any existing one.
  2. Send each request to the modules that can serve it, without being told which module belongs to which task.
  3. Keep every protected capability within a declared budget over any sequence of updates, including slow ones.
  4. Decline rather than answer without calibrated support.
  5. Record, for every answer, what produced it and why it was allowed.

Interactive

Try the promotion gate's rules

Two calculators built from the rules as published. They are not the UMNA source, which is private; the first reproduces the gate minimums recorded in the result files exactly.

When can the gate decide at all?

With fewer rows than a one-sided non-inferiority test at margin E needs, the gate does not decide and nothing is promoted. Minimum rows = ((zα + zβ) · √(2·var) / E)², never below the tier floor, where var is the sample variance of the origin's per-row correctness.

α = 0.10 and power 0.80 are the values that reproduce the recorded minimums: 293 (spambase), 424 (qsar-biodeg) and the floor of 50 (banknote).

Why a cumulative budget, not just a step test?

A toy, noise-free model of the two rules. Each new version is a little worse than the one serving. The step test compares it with the version serving now (tolerance ε); CCE also compares it with the very first version (budget E).

Status, honestly

Early evidence, not proof

  • Small models and simple public data: OpenML CC18 binary tasks and UCI Multiple Features.
  • NICE-R's advantage over simpler planners did not replicate across seeds, and combining Wings helped on only one dataset of seven. Both claims are open.
  • The promotion gate never let a poisoned version through, but two harmless-looking clean retrains that were slightly worse did pass.
  • Runs that route requests use host-measured latency, so two runs of the same seed can route a few rows differently.

Why the code is not open yet

Evidence first

Releasing code for claims that have not been shown to hold invites people to build on them. The evidence is published first, in a form anyone can check. When the core claims hold up in preregistered tests that replicate, on more than one kind of data, and survive outside review, the project will be released under AGPL-3.0 on an open-core model.
